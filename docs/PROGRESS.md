## Decisions

1. **Milestone mapping.** The instructions name M1 Foundation, M2 Visualization, M3 Differentiators; STORIES.md has M1–M6. Mapping: M1 Foundation = stories M1 (S-001–S-008); M2 Visualization = stories M2–M4 (S-009–S-022: sidebar, pause, logs, retention, search, filters, keyboard); M3 Differentiators = stories M5–M6 (S-023–S-032: detectors, menu bar, notifications, polish). The instructions' M4 is release prep (no stories).
2. **Repo layout.** Monorepo: `ingest/` (Go), `app/` (Swift package from the BAMA template), `scripts/`, `docs/`. One git repo at the root.
3. **Detectors run in the app (Swift, MagnifeKit),** not in the helper, so they are unit-tested with `test-mac-app` as instructed and the app stays a read-only consumer. To keep them cheap, the helper promotes the attributes they need into columns (`db_system`, `db_statement`, `http_method`, `http_status_code`, `http_route`, `http_url`), reading both old and new semantic-convention names.
4. **Trace rows are recomputed by the helper** from the trace's spans after every batch that touches them, so late spans and missing roots are always consistent. Trace status: Error if any span is Error, else the root's status.
5. **Route** = `"<method> <http.route>"` when the root span has both (matches the UX example "POST /orders"), else `http.route`, else the root span name.
6. **App-owned state stays out of magnife.sqlite.** The app never writes the database, so saved filters, retention choice and UI preferences live in UserDefaults. The app tells the helper the retention with `--retention` and the `retention <seconds>` stdin command; the helper prunes.
7. **Helper protocol** is JSON lines on stdout (`ports`, `batch`, `pruned`, `error`) and text commands on stdin (`retention`, `prune`, `retry`); EOF on stdin means exit. Written into `docs/schema.sql`.
8. **Metrics are accepted and dropped** on both gRPC and HTTP (`/v1/metrics`), so SDKs that export metrics by default don't log export errors. Showing metrics is v0.2.
9. **Busy-port detection lives in the helper**: before binding, it checks for any other listener on the port (any address) and reports it as busy with the owner's name, instead of binding 127.0.0.1 next to a `*:port` listener.
10. **Minimum macOS stays 26** (brief decision); the build uses the installed Xcode 27 SDK and Swift 6.4 tools. `swift-tools-version: 6.4` (template pinned 6.2).
11. **Decoding uses Collector pdata** (`ptraceotlp`/`plogotlp`/`pmetricotlp`), not the full `otlpreceiver`: same decoders and gRPC services, without the Collector component framework; we need our own listeners for the busy-port check anyway.
12. **SQLite in Go is modernc.org/sqlite** (pure Go, CGO_ENABLED=0), so the amd64 slice cross-compiles without a C toolchain. Page cache 16 MiB.
13. **Helper exit budget:** on stdin EOF, queued data is committed for up to 700 ms, then dropped and counted on stderr. Stdin lines over 4 KiB are ignored. Busy-port owner name comes from `ps`.
14. **The app waits for the helper before opening the database.** A read-only connection cannot open a WAL database whose `-wal` file is missing (verified, see below), which is the state after the helper closes cleanly. The app opens the db after the helper's `ports` event and retries every 2 s. Not adopted: SQLITE_FCNTL_PERSIST_WAL in the helper (would let the app read stored data if the helper cannot start at all); revisit if that case matters.
15. **A service scope** (sidebar) shows every trace with any span from that service; the sidebar count is traces with an Error span from it.
16. **Traces vs Logs** is a toolbar segmented control plus View > Traces ⌘1 / Logs ⌘2 (docs/ux.md). Pause is ⌃⌘P (⌘P is Print).
17. **Duration format:** "850 µs", "4.6 ms", "240 ms", "1.24 s", "12.4 s", "2 min 5 s".
18. **Settings keeps the template's Appearance tab** (accent picker, "System" default) next to General and Notifications.
19. **Commits are checkpoints until you replay them** (see Log). One checkpoint per story, Conventional Commit messages.
20. **Seed data through the real helper** (STORIES "Seed data"): snapshots and the self-test seed /tmp databases with `tools/seed.zsh`; the helper uses port 0 and reports the real port in its `ports` line, so seeding never touches 4317/4318 or collides with other runs. The seed set is deterministic (fixed ids, times relative to now), so self-test checks name exact routes and counts.
21. **Busy-port banner states in snapshots** are replayed `ports` lines (APP_HELPER=none has no helper); the real behavior is proven by the self-test with real port holders (a socket on 127.0.0.1 and one on 0.0.0.0). The owner the self-test sees is "Magnife" (it holds the ports itself).
22. **Receiver status position:** docs/ux.md asks for the leading edge of the detail column. SwiftUI on macOS 26 puts a detail-column `ToolbarItem` at the trailing edge (a following `ToolbarSpacer(.flexible)` does not move it; `.navigation` moves it to the window's leading edge, before the title). Kept trailing in the detail column for now; revisit when S-003 adds the Copy Environment Variables and Search buttons next to it.
23. **Helper `error` lines** show the app-wide banner "The receiver reported a problem: <message>" with Try Again, which sends `retry` and clears it; a helper that cannot launch at all keeps its own banner with a close button (Try Again could not help).
24. **Environment variables (S-003): one protocol on every tab,** OTLP/HTTP with protobuf on the receiver's HTTP port. All five SDKs export it; .NET and Python default to gRPC, so every tab sets `OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf` explicitly. Lines are `export NAME=value` (as in scripts/interop/README.md), so a paste into a shell sets them for the app it starts; the service name is `my-service`, because a `<your-service>` placeholder would be a redirect in a shell. Python adds `OTEL_PYTHON_LOGGING_AUTO_INSTRUMENTATION_ENABLED=true`; a one-line note under the block (not copied) names the step that is not a variable: `opentelemetry-instrument`, `-javaagent:opentelemetry-javaagent.jar`, `AddOtlpExporter()`, `NodeSDK`, the Go HTTP exporters. Java is the one tab scripts/interop does not cover (no JDK on this Mac); its lines follow the Java agent's documented variables.
25. **The port shown** is the HTTP port in the helper's last `ports` line, else the one it was started with (APP_HTTP_PORT), else 4318.
26. **The toolbar popover is part of S-003** (docs/ux.md, Toolbar item 8): the `terminal` button opens the same tabs and button; Edit > Copy Environment Variables (⇧⌘C) copies the last chosen tab without opening it; Help > Show Environment Variables opens it and replaces the default Magnife Help item. Copy Environment Variables is the default button (Return copies), the one prominent button while the list is empty.
27. **ContentUnavailableView gives its actions only the description's width,** which clipped the variables at about 280 pt. The trace list measures its width and gives the setup the column's width (minus margins, at most 520 pt); the code block scrolls sideways only when that is still too narrow.
28. **The popover snapshot** (`02-trace-list-environment-*`) is cropped from a window capture, because `screencapture -l` on a popover also takes its parent window and `-R` is refused without full Screen Recording. Where the popover extends past the main window, the crop shows a dark band behind its glass; that is the capture, not the app.

29. **Service colors (S-004): docs/ux.md's ten colors in first-seen order,** not the scaffold's 12-slot name hash. The hash gave two of three services the same color about one time in four, and its palette held orange, the findings color. `ServiceColors` ranks services by `first_seen_ns`, then name, so the first ten never share a color; the ranks never shift, because the helper never deletes a services row and its upsert changes only `last_seen_ns`. Past ten services the colors repeat in the same order. A service the app has not read yet gets the hashed slot until the next read places it.
30. **Holding still (S-004, design decision 6):** the list holds whenever its table is more than 4 pt from the top. While held, reads take rows that existed at the base seq and changed since (updated in place, never moved) and count traces with `first_seq > base` in the scope; nothing is inserted. The top (scrolling back, the button, or Trace > Show Newest Traces) reads the first page again. S-010 Pause will hold through the same reads. SwiftUI's Table has no scroll position on macOS, so `TraceListScroller` observes the NSScrollView it finds from a zero-size view inside a cell, and the row offset accounts for the toolbar inset and the column headers.
31. **Paging:** 200 rows a page (docs/ux.md, S-030). The next page is read when the last row's cell appears, and only while scrolled down, since AppKit can prepare rows outside the view; the top reads only the first page.
32. **Show Newest Traces** has no shortcut (docs/ux.md's Trace menu lists none) and is enabled only while the button shows, through `MenuState` (SwiftUI commands do not observe AppModel).
33. **VoiceOver row words:** SwiftUI's TableRow has no accessibility label, so each cell carries its spoken part (service, route, "240 milliseconds", "18 spans", status) and VoiceOver reads them in column order; the sentence is unit-tested (`TraceSummary.accessibilityLabel`). Not checked with VoiceOver running: SwiftUI's cell elements are not reachable by walking NSAccessibility children in process.
34. **The new-traces snapshot sets the held state** (the five seed traces fit the window); the self-test holds the real table by scrolling it with 350+ traces.

35. **The waterfall is an NSOutlineView (S-005),** not a SwiftUI List or Table: it draws only the rows on screen at any span count, gives disclosure triangles, ← → and ⌥-click for whole subtrees, and VoiceOver's outline levels without code, and its cells are plain AppKit views (no NSHostingView per row). The MVP allows AppKit for performance. Expansion state lives in `AppModel.collapsedSpans` (span ids), so it survives a rebuild of the tree; the coordinator writes it back from the outline's expand and collapse notifications and re-applies it after a reload. SwiftUI's List was not measured for 30,000 rows.
36. **Auto-collapse rule (design decision 7):** above 500 spans the tree opens level by level while the rows shown stay within 500, and every span with children below that level starts collapsed; the root's children always show. The `--huge-trace` shape (fanout 6) opens with 259 rows at 1,000, 5,000 and 30,000 spans. 500 is kept: speed does not need it (30,000 rows expand in about 120 ms), it keeps a big trace readable at a glance.
37. **The waterfall reads only its columns** (`waterfallSpans`: id, span id, parent, name, kind, start, duration, status, service), so a 30,000-span trace never decodes attribute or event JSON; the span detail (S-006) reads one full `SpanRecord` with `TelemetryReader.span(traceID:spanID:)`, added here.
38. **Waterfall row layout:** the duration sits at the trailing edge of the Span column, where no bar can cover it; a collapsed span's "N spans" is drawn after its bar (right, else left; with room on neither side the tooltip and VoiceOver label carry it), because the Span column is too narrow for it at depth. When the Span column runs out of room the service name gives way before the span name and is not drawn below about three letters; the tooltip reads "name · service" (an orphan's reads exactly "Parent span not received"). Error spans show the octagon and a red bar (S-005 UX: icon plus color); the word "Error" is in the VoiceOver label, not on the row.
39. **Live waterfall refresh:** after a batch the app reads the open trace's row and re-reads its spans only when `updated_seq` (or the span count) changed. The 500 ms redraw cap under load is left to S-030.
40. **Expand All Spans / Collapse All Spans** (docs/ux.md menus, ⌥⌘→ / ⌥⌘←) came with S-005, with the row context menu's two items; Copy Span ID is left to the span detail stories. Collapse All selects the root of a hidden selection.
41. **`APP_SELFTEST_ONLY=waterfall`** runs the reader, model and waterfall checks only, for quick rounds; `tools/selftest.sh` without it runs everything.
42. **The span detail split is an NSSplitView** (`DetailSplit`), not SwiftUI's VSplitView, which can neither place nor remember its divider nor hide a pane. Each pane is an NSHostingView (`sizingOptions = []`), so it gets the model and the accent again. The divider keeps its fraction through every resize (`splitView(_:resizeSubviewsWithOldSize:)`; AppKit's own resize split the change evenly and left 50 / 50), and a drag saves the new fraction to UserDefaults (`detail.splitFraction`); test and snapshot runs never save it. Its visibility is `detail.showsSpanDetail`.
43. **No Span | Trace Logs picker yet.** docs/ux.md puts it at the top of the span detail; it comes with S-012, since a picker with one working segment is noise. ⌥⌘1 / ⌥⌘2 come with it.
44. **Span detail content:** the status message sits under the kind · duration · status line (it explains an Error); Resource lists `service.*` first, then by key; an event's time reads from the span's start ("at 400 µs", "at −1.0 ms" for clock skew). Scope, links and ids are not shown in v0.1 (not in the UX block); the span ID is one Copy Span ID away.
45. **Values never hyphenate.** SwiftUI's Text hyphenates long words, which put a "-" that is not in the value into `Microsoft.EntityFrameworkCore.DbUp-dateException`. SwiftUI has no hyphenation setting; `.typesettingLanguage("zxx")` (no linguistic content) turns it off, checked with ImageRenderer at 240 pt: long identifiers then break between characters with no hyphen.
46. **"Show All" is measured, not guessed:** each value renders its full text hidden at the same width, and "Show All" shows when that is taller than the three-line text (`ValueLayout`). Expanded values live in `AppModel.expandedValues` (cleared when another span is selected), so the self-test and snapshots can open one; the self-test reads `valueLayouts`.
47. **Seed data gained span events:** the orders gRPC server span of the healthy trace has otelgrpc's `message` events (RECEIVED at 0.4 ms, SENT at 118.6 ms), so the Events section has real content in snapshots. Span and log counts are unchanged (37, 18).
48. **Copy Span ID** (ux.md Edit menu and row context menu, no shortcut there) came with S-006: Edit > Copy Span ID, the row's context menu (the clicked row), and ⌘C while the waterfall has focus (`WaterfallOutlineView.copy(_:)`).
49. **Menu titles in the self-test:** SwiftUI retitles a command (Show Span Detail / Hide Span Detail) only when its menu opens, so the self-test checks `MenuState`, which the commands read, as the test-mac-app skill advises. Not checked from outside through Accessibility tonight (that needs a computer-use grant): open View with a trace selected, press ⌃⌘I twice.
