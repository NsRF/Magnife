## Decisions

1. **Milestone mapping.** The instructions name M1 Foundation, M2 Visualization, M3 Differentiators; STORIES.md has M1–M6. Mapping: M1 Foundation = stories M1 (S-001–S-008); M2 Visualization = stories M2–M4 (S-009–S-022: sidebar, pause, logs, retention, search, filters, keyboard); M3 Differentiators = stories M5–M6 (S-023–S-032: detectors, menu bar, notifications, polish). The instructions' M4 is release prep (no stories).
2. **Repo layout.** Monorepo: `ingest/` (Go), `app/` (Swift package from the BAMA template), `scripts/`, `docs/`. One git repo at the root.
3. **Detectors run in the app (Swift, MagnifeKit),** not in the helper, so they are unit-tested with `test-mac-app` as instructed and the app stays a read-only consumer. To keep them cheap, the helper promotes the attributes they need into columns (`db_system`, `db_statement`, `http_method`, `http_status_code`, `http_route`, `http_url`), reading both old and new semantic-convention names.
4. **Trace rows are recomputed by the helper** from the trace's spans after every batch that touches them, so late spans and missing roots are always consistent. Trace status: Error if any span is Error, else the root's status.
5. **Route** = `"<method> <http.route>"` when the root span has both (matches the UX example "POST /orders"), else `http.route`, else the root span name.
6. **App-owned state stays out of magnife.sqlite.** The app never writes the database, so saved filters, retention choice and UI preferences live in UserDefaults. The app tells the helper the retention with `--retention` and the `retention <seconds>` stdin command; the helper prunes.
7. **Helper protocol** is JSON lines on stdout (`ports`, `batch`, `pruned`, `error`) and text commands on stdin (`retention`, `prune`, `retry`); EOF on stdin means exit. Written into `docs/schema.sql`.
8. **Metrics are accepted and dropped** on both gRPC and HTTP (`/v1/metrics`), so SDKs that export metrics by default don't log export errors. Showing metrics is v0.2.
9. **Busy-port detection lives in the helper**: before binding, it checks for any other listener on the port (any address) and reports it as busy with the owner's name, instead of binding 127.0.0.1 next to a `*:port` listener.
10. **Minimum macOS stays 26** (brief decision); the build uses the installed Xcode 27 SDK and Swift 6.4 tools. `swift-tools-version: 6.4` (template pinned 6.2).
11. **Decoding uses Collector pdata** (`ptraceotlp`/`plogotlp`/`pmetricotlp`), not the full `otlpreceiver`: same decoders and gRPC services, without the Collector component framework; we need our own listeners for the busy-port check anyway.
12. **SQLite in Go is modernc.org/sqlite** (pure Go, CGO_ENABLED=0), so the amd64 slice cross-compiles without a C toolchain. Page cache 16 MiB.
13. **Helper exit budget:** on stdin EOF, queued data is committed for up to 700 ms, then dropped and counted on stderr. Stdin lines over 4 KiB are ignored. Busy-port owner name comes from `ps`.
14. **The app waits for the helper before opening the database.** A read-only connection cannot open a WAL database whose `-wal` file is missing (verified, see below), which is the state after the helper closes cleanly. The app opens the db after the helper's `ports` event and retries every 2 s. Not adopted: SQLITE_FCNTL_PERSIST_WAL in the helper (would let the app read stored data if the helper cannot start at all); revisit if that case matters.
15. **A service scope** (sidebar) shows every trace with any span from that service; the sidebar count is traces with an Error span from it.
16. **Traces vs Logs** is a toolbar segmented control plus View > Traces ⌘1 / Logs ⌘2 (docs/ux.md). Pause is ⌃⌘P (⌘P is Print).
17. **Duration format:** "850 µs", "4.6 ms", "240 ms", "1.24 s", "12.4 s", "2 min 5 s".
18. **Settings keeps the template's Appearance tab** (accent picker, "System" default) next to General and Notifications.
19. **Commits are checkpoints until you replay them** (see Log). One checkpoint per story, Conventional Commit messages.
20. **Seed data through the real helper** (STORIES "Seed data"): snapshots and the self-test seed /tmp databases with `tools/seed.zsh`; the helper uses port 0 and reports the real port in its `ports` line, so seeding never touches 4317/4318 or collides with other runs. The seed set is deterministic (fixed ids, times relative to now), so self-test checks name exact routes and counts.
21. **Busy-port banner states in snapshots** are replayed `ports` lines (APP_HELPER=none has no helper); the real behavior is proven by the self-test with real port holders (a socket on 127.0.0.1 and one on 0.0.0.0). The owner the self-test sees is "Magnife" (it holds the ports itself).
22. **Receiver status position:** docs/ux.md asks for the leading edge of the detail column. SwiftUI on macOS 26 puts a detail-column `ToolbarItem` at the trailing edge (a following `ToolbarSpacer(.flexible)` does not move it; `.navigation` moves it to the window's leading edge, before the title). Kept trailing in the detail column for now; revisit when S-003 adds the Copy Environment Variables and Search buttons next to it.
23. **Helper `error` lines** show the app-wide banner "The receiver reported a problem: <message>" with Try Again, which sends `retry` and clears it; a helper that cannot launch at all keeps its own banner with a close button (Try Again could not help).
24. **Environment variables (S-003): one protocol on every tab,** OTLP/HTTP with protobuf on the receiver's HTTP port. All five SDKs export it; .NET and Python default to gRPC, so every tab sets `OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf` explicitly. 104. **One query language (S-017), in MagnifeKit:** `TraceQuery` parses text into a `TraceFilter` and formats a filter back (round trip unit-tested), so Search, the filter bar and saved filters (S-021) share it. 105. **Matching rules (`TraceFilterSQL`, bound values only):** Any Field looks at the trace's service, route and trace ID, each span's name and service, and the *values* of span and resource attributes (not keys: "http" would match every span); the raw JSON is checked with LIKE first and json_each confirms only those rows. "contains" ignores the case of A to Z (LIKE, as "Body contains"), `%` and `_` are plain. "is" compares a string's text, or a number's or bool's JSON ("500", "true"). Each attribute condition is met when any span (or its resource) matches; "is not" keeps traces in which no span has that value. Status is `traces.status` as the helper computes it.
106. **Search reads in two steps (S-017):** an empty field lists the 10 newest traces; otherwise a query that looks into spans first walks the newest 2,000 traces, newest first, checking each one's own spans (spans_by_trace) and stopping at 50 matches, so a common word answers in about 1 ms at any size; with fewer matches there, one pass over the store returns the page and its total (`COUNT(*) OVER ()`). When the page came without its total, `searchCount` follows and "50 of 312" fills in. Every keystroke cancels the read before it (GRDB interrupts the statement). Words of 8 to 32 hex digits skip the walk and put traces whose ID starts with them first. Search reads every stored trace: the sidebar, the filter bar and Pause do not narrow it.

Candidate for S-030 if 300,000-span stores feel slow.
108. **The Search panel is an overlay in the main window,** not a child NSPanel: one window to capture and focus, and a click outside lands on the overlay's catcher, which closes it. Liquid Glass (a floating control), 640 pt wide, under the toolbar. The field is an AppKit NSTextField because the field editor takes ↑↓, Return and Esc before SwiftUI's key handlers; ⌘Return is the footer button's key equivalent (the field editor never sees it). Token chips sit under the field, not inside it (a token field would fight free-text parsing). Suggestions (up to 8) come before the traces in one list for ↑↓; Return or a click completes the token. The field starts empty each time Search opens; ⌘K while it shows selects the text.

It shows only in the Traces view; each view keeps its own bar's visibility, and ⌘F and the Filter button act on the current one. The bar's visibility is not remembered across launches (filters are not saved either until S-021).
112. **Esc in a list hides its filter bar** with `.onKeyPress(.escape)` on the table: `onExitCommand` never fires while a SwiftUI Table has the focus (FIXLOG). The rest of the Esc order (span detail and waterfall focus) comes with S-022.
113. **Search's full read picks how to read spans (refines decision 106):** when the trace's own columns (service, status, duration, route) leave at most 5,000 traces, each one's spans are read through spans_by_trace; otherwise every span is read once. 100,000 spans: "orders status:error >100ms ht" 23 ms (was 140 ms under load), "service:orders paymnt" 69 ms; 300,000 spans stay at one pass (up to 243 ms).
114. **"Slower than" accepts** a number (milliseconds) with an optional `>` and an optional unit `ms`, `s`, `us`, `µs` or `ns`, spaces anywhere, any case; digits and one point only (no signs, exponents, commas or full-width digits), and above zero. "m" and "min" are refused: minutes are not a sensible trace threshold and "m" could be read as milli. It keeps traces strictly slower (`duration_ns >`), so ">200ms" leaves a 200 ms trace out. The normalized text uses up to three decimals ("1.25 s", "850 µs"), and the token writes it without spaces (">1.5s", ">850us").
115. **A bad "Slower than" keeps the last valid rule** (docs/ux.md) and the Filter button stays as that rule says; the error sits beside the field and wraps rather than widening the column (a fixed-width error stretched the list column in the first snapshot).
116. **Condition rows (S-020) are drafts until they mean something:** a row needs a key, and a value unless it is "exists"; ">" and "<" need a number. Typing "route" or "any field" in the key means the built-in key (decision 104). The operator in effect follows the key (Any Field forces "contains"). Key suggestions are inline under the row being edited (6 visible, up to 20, scrolling), not a popover: a popover would take the key window from the field being typed in. Log keys (`attribute_keys.source = 3`) are not offered: logs are not trace filters. A key typed in full hides the suggestions until it changes. Esc in the key field puts the suggestions away first, then hides the bar.
117. **No alias between old and new semantic-convention keys in conditions:** `db.system` does not find spans that only carry `db.system.name` (the .NET seed spans). Conditions name the key as sent; the promoted columns already merge both names for the detectors (M5). A candidate for later if people ask.
118. **Saved filters live in UserDefaults** (decision 6) as one JSON array under `savedFilters` (`SavedFilter`: id, name, query in the S-017 language), in the order created. Snapshot and self-test runs (APP_SNAPSHOT, --selftest) and other APP_STORE runs use their own suite, `com.nasserfarhat.magnife.tests` (`AppDefaults.shared`), reset at the start of each run, so tests never touch what people saved. Snapshot runs seed "Checkout errors" (`service:checkout-api status:error`) through the model's Save Filter path (STORIES.md, Seed data).
119. **A selected saved filter owns its scope:** the sidebar row is the saved filter, and its service is `savedFilterService`; the Service pop-ups change that (the title reads "— Edited") instead of leaving the saved filter. Choosing another sidebar row keeps the filter bar's filters on, as a service row always did (the sidebar sets the scope only); Clear Filters resets everything to All Services, and its Undo returns to the saved filter. Selecting a saved filter applies its parts as one change (`holdsFilterChanges`), one read.
120. **Save Filter on an unchanged saved filter is disabled** (reads "Save Filter"; nothing to save, like Save on an unchanged document); Save Filter As… needs a saved filter selected and a filter on; both only in the Traces view. Names are trimmed and unique ignoring case. In-place rename keeps the old name on an empty or duplicate name (a duplicate beeps; the sheet is where the duplicate message shows); focus leaving the field keeps the new name, as in Finder.
121. **Deleting the selected saved filter leaves its filters on**, with the sidebar on its service, so the list does not jump; Undo puts it back in its place and selects it again. Delete Filter (⌘⌫) is enabled only while the sidebar List has the focus (`sidebarHasFocus`, from `@FocusState` on the List), so ⌘⌫ still deletes to the line start in text fields.
122. **Keys are handled where they arrive, with the rules in MagnifeKit** (`KeyboardNavigation.swift`): the waterfall's ← → follow `Waterfall.moveLeft/moveRight` in `WaterfallOutlineView.keyDown` rather than NSOutlineView's defaults, so they do exactly what docs/ux.md says; Home / End / Page keys move the selection in lists and the waterfall (NSTableView alone only scrolls); Return in the trace list is the Table's primary action, so a double-click also moves into the waterfall. Tab moves between columns explicitly (`FocusColumn.next`); inside the filter bar AppKit's own key view order applies. The sidebar's Tab goes through a local key monitor (`SidebarTabKeys`), because the sidebar List takes ⇧Tab before `onKeyPress` sees it.
123. **The span detail takes the focus as one focusable scroll view** (system focus ring), so Esc and Tab work there and Full Keyboard Access reaches its buttons; arrow keys do not scroll it (the scroll wheel, VoiceOver and Full Keyboard Access do). A focus request is taken once (`takeFocusRequest`), so a span detail that appears again never steals the focus from the waterfall.
124. **The self-test posts real key events** (`NSApp.postEvent`, so the app's key monitors see them) and audits `NSApp.mainMenu` against docs/ux.md section 1 (title, key, modifiers) and for shortcuts used twice. ⌘F runs the item's action in the self-test: SwiftUI enables menu items on its own schedule while another app is in front (test-mac-app); the audit checks its shortcut.
125. **Test runs leave the user's layout alone** (FIXLOG): `AppDefaults.protectLayout` / `restoreLayout` copy AppKit's own "NSWindow Frame …", "NSSplitView Subview Frames …" (and table and toolbar) keys aside in the test suite and put them back exactly; the real app's split-frames and main window frame keys were deleted once (a copy of the domain is in the session scratchpad), so a normal launch opens at 1280 × 760 with the columns at 210 / 520 / the rest. Snapshots therefore open at 1280 × 760 too.
126. **Pruned services and keys are left out by the reader, not deleted by the helper** (M2 review finding 8): the contract keeps `services` as every service ever seen and `attribute_keys` as every key; the sidebar lists a service only while a span or log of it is stored (EXISTS on `spans_by_service_status` and `logs_by_service`, `ServiceScopeTests` still pins the covering index), and suggestions offer a key only when it was last seen inside the retention. Deleting rows in the helper would change both tables' documented meaning (a contract change for the same effect). Service colors follow the listed services, so a pruned service frees its color slot.
127. **The retention lives in the supervisor, not only in the launch configuration:** `HelperSupervisor.setRetention` stores it on the supervisor's queue and every launch, restarts included, passes it; `retention <s>` goes to a running helper at once, and a change while the helper is down is not lost (review finding 1).
128. **After Search's Return and after a sheet closes, the list takes the focus only if nothing has it** (the window itself is first responder): a field or column people moved to meanwhile keeps it, and a Search reopened in between keeps its field. Single main window, so window tabbing is off (no Show Tab Bar / Show All Tabs in View).
129. **Resume reads at most 5,000 rows** (`TraceList.resumeMaxRows`): enough for the selected row (it moves down by at most the number of new traces) plus a page. A selection deeper than that stays selected and open in the detail column while the list shows its newest rows; nothing selected reads one page however long the pause. Until the reveal ends, refreshes read the same number of rows (review findings 2 and 3).
130. **Quoted keys in the query language:** `"key"` right before `=`, `!=`, `~`, `>` or `<` is always an attribute key, whatever it holds (so an attribute literally named `route` or `any field` stays an attribute); `has:` takes a quoted key too. Formatting quotes only keys the bare form cannot carry, so every saved query from before reads the same.
131. **Open Trace in Trace Logs selects the log's span** (docs/ux.md lists ⌘O "from the Logs view or Trace Logs" and the item in both context menus): the trace is open already, so Open Trace there does what Return does, select the span and focus the waterfall. It is enabled only while Trace Logs shows a selected log whose span is in the waterfall.
132. **The span detail's Logs section has no selected log** (narrows S-011's flow "⌘C copies the selected log's body", review finding 10): its rows are part of a read-only inspector whose bodies are selectable text, so ⌘C copies the selected text and the row's context menu has Copy Body for the whole body; the same logs as selectable rows, with ⌘C and Edit > Copy Body, are one click away in Trace Logs (⌥⌘2). Keeps decision 123 (the span detail is one focusable scroll view).
133. **One layout backup per test run** (refines decision 125): `layout.backup.<pid>` in the test suite; a run that starts while another lives copies that run's backup, since the domain may already hold the other run's frames; a dead run's backup is restored at the next test launch.
